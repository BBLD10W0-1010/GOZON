# HM1 — консольный таск-трекер на Go

Решение домашнего задания №1: интерактивный режим, все шесть операций,
файловое хранение, фильтры, поиск, пагинация, импорт и модульные тесты.
Go 1.22 или новее; только стандартная библиотека, внешних зависимостей нет.

## Запуск

Из папки `HM1`:

```sh
go run ./cmd/tasktracker
```

Программа остаётся запущенной до `exit` или конца стандартного ввода.
Команда `help` показывает все команды и их параметры.
Данные по умолчанию сохраняются в `data/tasks.json` относительно текущей
рабочей папки. Каталог создаётся при первой успешной записи.
Чтобы использовать другой файл:

```sh
go run ./cmd/tasktracker -data "data/my-tasks.json"
```

## Пример сеанса

```text
add --title "Изучить Go" --deadline 2099-12-30
add --title "Написать тесты" --deadline 2099-12-31
list
get 1
status 1 in_progress
edit 1 --title "Изучить интерфейсы Go" --deadline 2099-12-29
list --status in_progress --search "GO" --page 1 --limit 5
list --overdue
status 1 done
delete 1
import "examples/import.json"
exit
```

Заголовки и пути с пробелами заключаются в одинарные или двойные кавычки.
Внутри кавычек можно экранировать такую же кавычку обратной косой чертой.
Обычные обратные косые черты в путях Windows сохраняются.

## Правила

- ID — положительное число, которое выдаёт приложение. Счётчик `next_id`
  хранится в файле независимо от задач: удалённые ID не используются повторно,
  в том числе после перезапуска и удаления всех задач.
- Статусы: `planned`, `in_progress`, `canceled`, `done`. Новая задача получает
  `planned`. Повторная установка текущего статуса запрещена.
- `done` и `canceled` — конечные статусы: разрешено только удаление.
- Пустой заголовок, включая пробельный, запрещён. Крайние пробелы удаляются.
- Дедлайн — календарная дата `YYYY-MM-DD`. Сегодняшняя дата допустима;
  просрочка начинается на следующий день по местному календарю компьютера.
  В JSON дата хранится как полночь UTC; это представление даты, не времени суток.
- При редактировании проверяются новые значения. Можно изменить только
  заголовок просроченной задачи, не перенося её существующий дедлайн.
- Список всегда сортируется по дедлайну, затем по ID. Фильтры применяются
  перед пагинацией. Поиск без учёта регистра, в том числе для кириллицы.
- `--overdue` исключает завершённые и отменённые задачи.
- По умолчанию `page=1`, `limit=20`; оба должны быть положительными.
  Пустая выборка имеет 0 страниц; страница за пределами выборки пуста.
- Ошибка команды выводится пользователю, затем программа читает следующую
  команду. Ошибки запуска, ввода или вывода завершают процесс с кодом 1.

## Импорт JSON

Входной формат — массив объектов с `title`, `deadline` и необязательным
`status` (по умолчанию `planned`). Поле `id` и другие неизвестные поля
считаются ошибкой: ID выдаёт приложение.

```json
[
  {"title": "Первая задача", "deadline": "2099-12-30"},
  {"title": "Вторая задача", "deadline": "2099-12-31", "status": "in_progress"}
]
```

Корректные записи сохраняются вместе, некорректные пропускаются с сообщением
и номером записи, начиная с 1. В `examples/import.json` намеренно есть одна
некорректная запись для демонстрации. Синтаксически повреждённый JSON не
импортируется. Файл импорта и внутренний файл хранилища имеют разные форматы.

## Архитектура

```text
cmd/tasktracker/main.go       сборка приложения и запуск
internal/domain/task.go      Task, ID, Status, State, ошибки и правила дат
internal/service/service.go  бизнес-правила и интерфейс Repository
internal/service/import.go   обработка записей импорта
internal/storage/file.go     JSON-хранилище и замена файла через временный файл
internal/storage/memory.go   взаимозаменяемое хранилище в памяти
internal/cli/cli.go          команды, интерактивный цикл, форматирование
internal/cli/parser.go       разбор аргументов с кавычками
```

Интерфейс хранилища объявлен у потребителя в `service`, а не в `storage`.
Хранилище не печатает пользовательский вывод. Ошибки сохраняют причины
через `%w`, бизнес-ошибки можно проверить через `errors.Is`.
В `Task` нет дополнительных полей.

Чтобы переключиться на хранение в памяти, замените одну строку в `main.go`:

```go
repo, err := storage.NewFile(*data)
```

на:

```go
repo, err := storage.NewMemory()
```

В файловом режиме каждая успешная операция сразу сохраняется. Повреждённый
файл обнаруживается при запуске и не перезаписывается. Запись происходит
через временный файл в том же каталоге с последующей заменой. Предполагается
один запущенный процесс на один файл; межпроцессные блокировки не реализованы.

## Проверка

```sh
gofmt -l .
go build ./...
go vet ./...
go test ./... -cover
```

Тесты проверяют бизнес-правила, сортировку и фильтры, импорт с частичными
ошибками, сохранение после перезапуска, неизменность файла при неверной
записи, изоляцию памяти, разбор кавычек и восстановление после ошибок команд.
