## Домашнее задание №1 «Консольный таск-трекер»

Необходимо реализовать консольную утилиту для управления списком задач в формате интерактивного
режима: программа запускается один раз, читает команды из стандартного ввода и выполняет их до
выхода.

Программа должна обладать командой `help`, благодаря которой можно получить список доступных команд
с кратким описанием, и командой `exit` для завершения работы.

Задача описывается как минимум набором полей: **идентификатор**, **заголовок**, **статус** и
**дедлайн**. Идентификатор выдаёт само приложение при создании задачи — пользователь его не вводит.
Возможные статусы: `planned`, `in_progress`, `canceled`, `done`. Возможно введение дполнительных полей, но с обязательным коротким обоснованием в виде комментария над полем. 

Список задач необходимо сохранять в файл, чтобы после перезапуска программы задачи не терялись.
Формат файла остаётся на выбор.

Список команд для реализации:

1. **Добавить задачу**
   На вход принимается заголовок и дедлайн. Приложение само присваивает задаче уникальный
   идентификатор и статус `planned`. Пустой заголовок — ошибка. Дедлайн в прошлом — ошибка.
   Идентификаторы не должны переиспользоваться после удаления задач.
2. **Получить список задач**
   Метод выводит задачи, при этом одни и те же данные должны печататься одинаково
   при каждом запуске. Порядок сортировки — по дедлайну, при равных дедлайнах — по идентификатору.
   По желанию можно добавить опциональные параметры: фильтр по статусу и фильтр «только
   просроченные» — задачи, у которых дедлайн уже прошёл, а статус не `done` и не `canceled`.
3. **Получить одну задачу**
   На вход принимается идентификатор задачи. Если такой задачи нет, должно вернуть
   понятную ошибку, а не пустой результат.
4. **Изменить статус задачи**
   На вход принимается идентификатор задачи и новый статус. Перевести задачу в статус, который у
   неё уже стоит, нельзя. Задачу в статусе `done` или `canceled` менять нельзя — её можно только
   удалить.
5. **Отредактировать задачу**
   На вход принимается идентификатор задачи и новые значения заголовка и/или дедлайна. Ограничения
   те же, что и при создании: пустой заголовок и дедлайн в прошлом — ошибка. Редактировать
   завершённую или отменённую задачу нельзя.
6. **Удалить задачу**
   На вход принимается идентификатор задачи. Метод должен удалять задачу из вашего файла.

### Требования к коду:

1. Логика разбита на пакеты: предметная область, хранилище, бизнес-логика и работа с
   пользователем — разные пакеты. `main` только собирает приложение и запускает его.
2. Интерфейс хранилища объявлен **у потребителя** — там, где он используется, а не рядом с
   реализацией. Заменить хранилище в памяти на файловое должно быть возможно, поменяв одну строку
   в `main`.
3. Хранилище ничего не печатает и не возвращает готовых строк для вывода. Форматирование живёт в
   слое, который отвечает за общение с пользователем.
4. Ошибки не теряются: каждая возвращается наверх и оборачивается через `%w`.
5. Там, где значение имеет смысл (идентификатор, статус), заводите свой тип, а не просто `int` и
   `string`.
6. Перед сдачей должно быть чисто:

```bash
gofmt -l .            # пусто — все файлы отформатированы
go build ./...        # собирается
go vet ./...          # без замечаний
```

### Дополнительные задания:

1. Постраничная пагинация для команды *«Получить список задач»* по параметрам `page` и `limit`
   (по умолчанию `page` = 1, `limit` = 20). В выводе должно быть видно, сколько всего задач
   попало под фильтр и сколько всего страниц.
2. Поиск задач по подстроке в заголовке — без учёта регистра.
3. Команда импорта задач из JSON-файла: на вход принимается путь к файлу, все корректные задачи
   добавляются в трекер. Если хотя бы одна задача в файле некорректна, приложение должно сообщить,
   какая именно, и не сломаться на остальных.
4. Покрыть написанный код юнит тестами. 


### Подсказки и советы

- Чтение команд: `bufio.NewScanner(os.Stdin)`, разбор строки — `strings.Fields`, `strconv.Atoi`.
- Работа с файлом: `os.ReadFile`, `os.WriteFile`, `os.OpenFile`, `os.Create`.
- Сериализация: `encoding/json`, `json.Marshal` / `json.Unmarshal`. Помните, что `encoding/json`
  видит только экспортируемые (с большой буквы) поля структуры; имена в файле задаются тегами.
- Время: `time.Parse` с строкой вида `2006-01-02`, сравнение — `time.Time.Before` /
  `After`, текущий момент — `time.Now()`.
- Сортировка: `sort.Slice` или `slices.SortFunc`.
- Ошибки: `errors.New`, `fmt.Errorf` с `%w`, проверка через `errors.Is`. Для «задача не найдена»
  удобно завести отдельную ошибку в пакете и сравнивать с ней.
- Любую функцию стандартной библиотеки можно посмотреть прямо в терминале: `go doc time.Parse`.
- Грамотно разбивайте логику работы программы на пакеты и используйте интерфейсы.
